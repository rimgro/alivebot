# Доступ Alive к сайтам с проверкой браузера: исследование 12 октября 2026

## Вывод

Дополнение после реализации 12 октября: нативный запуск Chrome с ненулевым локальным CDP-портом и загрузкой первой страницы до подключения драйвера выбран по успешным проверкам на этом Mac. Через полный модуль Alive обе главные страницы Avito/Wildberries вернули 200 и были доступны для чтения. Результаты и границы проверки приведены в разделе 7 ниже. Первоначальная конфигурация и исследовательские предложения в разделах 1–6 относятся к состоянию до этого изменения.

Для локального Telegram-бота сначала следует проверить обычное окно Chrome через уже установленный Patchright, затем сравнить его с фактической сборкой Fortress в том же модуле, который обслуживает телефон. Универсальный доступ ко всем сайтам не подтверждён ни исследованными проектами, ни нашими тестами. Причина конкретного отказа Avito/Wildberries пока не установлена: оператор подтвердил блокировку своего экземпляра, но точная страница и текст ошибки не предоставлены.

На первоначальном этапе выполнены чтение кода и конфигурации, проверка первичных источников и локальный эксперимент на пустых страницах. Последующие анонимные открытия Avito/Wildberries, сравнение движков и изменение рабочего режима описаны в разделе 7. Вход в аккаунты и отправка форм не выполнялись.

## 1. Что фактически запускается в локальном боте

Проверенная конфигурация `alive.config.local.json`:

```json
{
  "enabled": true,
  "driver": "patchright",
  "channel": "chrome",
  "headless": true,
  "viewport": null,
  "cdpEndpointEnv": ""
}
```

При пустом `cdpEndpointEnv` метод `BrowserModule.ensurePage()` в `src/modules/browser/module.ts` запускает управляемый Chrome через `launchPersistentContext`. К внешнему Fortress он не подключается. В `src/runtime/tools.ts` отдельный инструмент Fortress добавляется только при отсутствии инструмента `browser` от модулей. Таким образом, присутствие зависимости Fortress не доказывает, что текущая задача Telegram-агента выполняется в нём.

Установленный SDK `tilion-fortress` имеет версию `151.0.7910`. Его наличие не подтверждает запуск бинарника, поколение движка или применение дополнительных Canvas-патчей. Документированный путь подключения существующего браузера уже есть: [Fortress/CDP](deploy/browser/fortress/README.ru.md).

### Локальный эксперимент

На этом Mac запускались два отдельных временных профиля Patchright 1.63.0 с Chrome 155.0.8059.39. Открывалась только пустая `data:`-страница; пользовательские профили, cookies и сайты не читались. После проверки браузеры закрыты, временные профили удалены.

| Параметр | `headless: true` | `headless: false` |
| --- | --- | --- |
| Часть `navigator.userAgent` | `HeadlessChrome/155.0.0.0` | `Chrome/155.0.0.0` |
| `navigator.webdriver` | `false` | `false` |
| `navigator.platform` | `MacIntel` | `MacIntel` |
| Язык / часовой пояс | `ru-RU` / `Europe/Moscow` | `ru-RU` / `Europe/Moscow` |

Измерение показывает доступный странице маркер headless в текущем режиме. Это кандидат на причину отказа, а не доказательство того, что конкретный сайт блокирует именно по нему. Успешное открытие пустой страницы не является тестом доступа к маркетплейсу.

Patchright рекомендует постоянный профиль Chrome, `headless:false`, `viewport:null`, без самостоятельной подмены User-Agent и заголовков. Заявления авторов о необнаружимости не следует считать гарантией. [Рекомендация разработчиков](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright-nodejs#best-practice---use-chrome-without-fingerprint-injection).

## 2. Разные отказы требуют разных решений

| Наблюдение | Что проверить | Реакция агента |
| --- | --- | --- |
| Временная страница проверки браузера | Продолжает ли работать JavaScript, завершается ли проверка, меняется ли документ | Ограниченно ждать завершения; затем передать человеку при необходимости |
| Видимая CAPTCHA | Наличие реального задания и состояние страницы после ручного решения | Передать ту же вкладку в Mini App, проверить результат перед продолжением |
| Постоянный отказ, HTTP 403 | Текст отказа, наличие challenge, доступ обычного ручного браузера | Остановиться; не выдавать любой отказ за решаемую CAPTCHA |
| HTTP 429 | Лимит и серверное время повторной попытки | Выдержать паузу; не запускать цикл повторов |
| Повторяющаяся проверка | Ошибки выполнения/загрузки, поддержка браузера, стабильность соединения | Диагностировать условия, не перезапускать профиль бесконечно |

Cloudflare учитывает заголовки, признаки браузера и характеристики сессии. Поэтому одного изменения движения мыши недостаточно для устранения всех причин отказа. Это описание механизмов Cloudflare, а не установленного поставщика защиты Avito/Wildberries. [Bot scores](https://developers.cloudflare.com/bots/concepts/bot-score/).

Для Cloudflare Challenge Page есть явный заголовок `cf-mitigated: challenge`; Alive уже распознаёт его. Он позволяет отличать challenge от обычного ответа сервера. [Документация заголовка](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/).

В Alive ответ главной навигации с таким заголовком, 403 или 429 сразу останавливает действия агента; известные видимые виджеты также вызывают передачу человеку. Отдельной стадии ожидания автоматической проверки до уведомления сейчас нет. Пауза команд не равнозначна выключению JavaScript страницы: сама проверка может продолжаться в браузере.

Cloudflare перечисляет нестабильную сеть, мешающие расширения, конфигурацию браузера и VPN/proxy среди причин проблем с проверками. Отдельный ответ 401 на запрос Private Access Token может быть нормальным запасным сценарием и сам по себе не доказывает блокировку. [Диагностика challenge](https://developers.cloudflare.com/cloudflare-challenges/troubleshooting/challenge-solve-issues/).

VPN оператора должен оставаться включённым. Сравнение режимов следует выполнять при неизменном разрешённом маршруте. Если обычный ручной Chrome тоже получает отказ, замена драйвера сама по себе не установит и не устранит причину.

## 3. Решения и приоритеты

| Вариант | Оценка для Alive | Что остаётся неизвестным |
| --- | --- | --- |
| Обычное окно Chrome + Patchright | Первый эксперимент: минимальное изменение режима, существующий профиль и пульт сохраняют архитектуру | Доступ к конкретным страницам Avito/WB |
| Fortress через существующий CDP-адаптер | Второй эксперимент: нативный Chromium-движок без полной переделки пульта | Реальная сборка, поколение, совместимость и результаты целевого сценария |
| Camoufox | Отдельный кандидат для сравнения после Chromium | Понадобится Firefox-адаптер для потока и подписания; выигрыш на целевых сайтах не измерен |
| Browserbase Verified | Коммерческий кандидат для ограниченного испытания | Покрытие российских сайтов, доступность, стоимость и совместимость телефонного интерфейса |
| Ещё один набор JS-подмен поверх текущего браузера | Не рекомендован как следующий шаг | Согласованность параметров и новые признаки вмешательства |
| Официальный API подходящей операции | Предпочтителен, когда операция действительно доступна оператору | Покрытие именно поиска/просмотра, а не только управления собственным магазином |

### Fortress: что подтверждает опубликованный тест

Разработчик публикует результат 159/184 успешных загрузок (86,4%) для Fortress v153 на 92 целях. Это его собственный тест, не независимая проверка. На каждую цель было две попытки в headless на облачных машинах US-East. Проверялась загрузка страницы, без кликов, ввода и отправки форм; Avito и Wildberries отсутствуют в опубликованном списке. Часть защит срабатывает на отправке формы, которую тест не выполняет. Метод Fortress также включает собственную логику ожидания. Поэтому проценты нельзя переносить на полноценную работу Alive или трактовать как чистое преимущество одного бинарника. [Методика и список целей](https://github.com/tiliondev/fortress/blob/main/docs/BENCHMARK.md).

Актуальный README описывает v3, подключение через CDP, ограничения сетевого доступа и активацию: без активации заявлен движок первого поколения. Также изменились условия распространения относительно ранних BSD-релизов. Перед обновлением необходимо проверить именно выбранную версию и бинарник; зависимость 151 в нашем проекте не равнозначна описанному v3. [README Fortress](https://github.com/tiliondev/fortress).

У текущего адаптера внешнего CDP один разрешённый владелец контекста. Для нескольких Telegram-пользователей нельзя подключать один общий default context: потребуются отдельные экземпляры/профили и управление их жизненным циклом. Наши проверки CDP подтверждали работу адаптера с внешним Chrome; они не измеряли доступ Fortress к маркетплейсам.

### Camoufox

Это Firefox с изменениями в движке. В собственной документации автор прямо признаёт перерыв в сопровождении, снижение эффективности и противоречия в отпечатках; проект снова развивается. Поэтому автоматическая замена рабочего Chromium на Camoufox без сравнения не обоснована. [Ограничения проекта](https://camoufox.com/stealth/).

Поток Alive и `BrowserSigningTransport` используют Chromium CDP, который Playwright поддерживает для Chromium. Интеграция Camoufox потребует отдельного решения этих частей. [CDP sessions](https://playwright.dev/docs/api/class-browser#browser-new-browser-cdp-session). Поддержка виртуального дисплея Linux у Camoufox документирована, но сама по себе не доказывает отсутствие детекта. [Параметры запуска](https://camoufox.com/python/usage/).

### Browserbase Verified

Провайдер предлагает специальный Chromium, распознаваемый его партнёрами по защите, и решение поддерживаемых CAPTCHA. Verified указан для плана Scale; покрытие Avito/WB этим описанием не подтверждено. [Identity](https://docs.browserbase.com/platform/identity/overview).

В Verified ограничена настройка viewport, а функция обозначена beta. Это конфликтует с автоматическим изменением размера удалённого браузера под телефон в Alive; для испытания нужно сохранять исходный viewport и масштабировать изображение на клиенте. [Ограничения Verified](https://docs.browserbase.com/platform/identity/verified-customization).

Готовый Live View позволяет смотреть и управлять браузером, но мобильная клавиатура официально не поддерживается и требует собственной передачи ввода. Это не готовая замена нашей Mini App. [Live View](https://docs.browserbase.com/platform/browser/observability/session-live-view). Покупка и подключение провайдера не выполнялись.

### Почему не следует наслаивать подмены

Исследование FP-Inconsistent выявляет противоречия между свойствами браузера и их изменениями во времени у сервисов, обещающих реалистичные отпечатки. Оно не оценивает нашу текущую сборку. Инженерный вывод: сначала измерять и устранять конкретные несоответствия, а не одновременно менять User-Agent, Canvas, язык и аппаратные свойства. [Исследование](https://arxiv.org/abs/2406.07647).

## 4. Что дают Web Bot Auth, профиль и пульт

Web Bot Auth подтверждает криптографическую идентичность бота. Cloudflare позволяет владельцам сайтов задавать собственные правила разрешения и блокировки AI-ботов; статус Verified не означает доступ ко всему Интернету. Нет подтверждения, что целевой сценарий Avito/WB принимает идентичность Alive. Статус нашей заявки в Cloudflare в рамках этого исследования не проверялся. [Web Bot Auth](https://developers.cloudflare.com/bots/reference/bot-verification/web-bot-auth/), [Verified bots и политики](https://developers.cloudflare.com/bots/concepts/bot/verified-bots/).

Постоянный профиль сохраняет состояние сессии. Он не отменяет решение сервера об отказе. При подключении Chrome через remote debugging нужен отдельный каталог профиля: начиная с Chrome 136 стандартный каталог Chrome не подходит для этих переключателей. [Изменение Chrome](https://developer.chrome.com/blog/remote-debugging-port).

Пульт телефона показывает и управляет той же удалённой вкладкой. Сайт продолжает видеть удалённый браузер и его соединение, а не Safari/Chrome телефона. Поэтому ручное решение CAPTCHA помогает там, где предлагается решаемая проверка, но не гарантирует устранение постоянного запрета.

Wildberries документирует API для продавцов и серверные лимиты, включая отдельные заголовки ожидания для 429. Этот API нельзя автоматически считать универсальным API покупательского поиска. [WB API](https://dev.wildberries.ru/openapi/api-information). Портал Avito Developers не удалось открыть данным исследовательским инструментом; покрытие API Avito не заявляется как проверенное решение.

## 5. Предлагаемая логика Alive

Первоначальный план по результатам исследования; выполненные изменения и их измерения приведены в разделе 7:

1. На старте фиксировать фактический движок, версию, режим, профиль и транспорт команды. `request` в нынешнем модуле — отдельный Node HTTP-клиент; для интерактивной страницы использовать навигацию браузера.
2. Различать готовую страницу, автоматическую проверку, запрос ручной помощи, ограничение частоты и постоянный отказ. При неопределённости сохранять причину неизвестной, а не выдавать догадку за диагноз.
3. При известной автоматической проверке приостановить действия агента и ограниченно ждать изменения страницы, сохраняя работу браузера. Начальный экспериментальный бюджет 15 секунд — параметр для измерения, не гарантия провайдера. Пароли/коды и явные интерактивные проверки сразу передавать человеку.
4. При необходимости открывать существующий пульт для владельца задачи. После возврата проверять фактическую страницу и состояние проверки; наличие HTTP 200 или клика на «Готово» само по себе не означает доступ.
5. При 429 соблюдать указанный сервером срок; при постоянном отказе прекращать автоматические повторы и сообщать причину. Не менять аккаунт, IP или отпечаток в цикле после запрета.
6. Выбирать проверенный движок как заранее установленную настройку сценария. Не пытаться переносить cookies и продолжать заблокированную сессию между несколькими движками автоматически.

Сохранить изоляцию пользователей, восстановление закрытого пульта, отзыв доступа и очистку сессий. Для обычной страницы агент и человек могут пользоваться браузером с сериализацией ввода; во время проверки/приватного ввода агент ждёт.

## 6. Как оценить результат

Сначала получить точную страницу и текст отказа. На неизменном разрешённом маршруте сравнить ручной обычный Chrome, Chrome/Patchright с обычным окном, затем конкретную сборку Fortress. У каждого варианта должен быть собственный выделенный постоянный профиль. На собственном стенде можно полноценно проверять автоматизацию; целевые сайты проверять в пределах разрешённого сценария, без обхода существующего бана.

Оценивать не только загрузку главной страницы, но и выполнение конкретной задачи: открыть нужную страницу, прочитать ожидаемые данные, при проверке передать вкладку, после возвращения продолжить действие. Раздельно учитывать загрузку, CAPTCHA, 403, 429, ошибки сети и завершение задачи. Объём испытаний не должен превышать допустимую нагрузку.

В диагностике хранить версию и режим, домен без приватной строки запроса, HTTP-статус, тип проверки, длительность и итог. Cookies, токены, тела личных страниц, ввод и ключи пульта исключить. До такого сравнения корректный статус: найдены проверяемые улучшения, доступ Avito/WB не подтверждён.

Приоритет: проверить режим обычного окна; подтвердить фактический Fortress в пути с пультом; затем добавить классификацию отказов и стадию ожидания автоматической проверки. Переписывать интерфейс телефона для этих первых шагов не требуется.

## 7. Реализация и измерения после исследования

### Реальные открытия главных страниц

Испытания выполнялись без входа в аккаунты, покупок или отправки форм, в отдельных профилях. VPN оставался включённым. В сравнении обычного драйверного Chrome и Docker/Fortress проверка внешнего адреса показала совпадающий выходной IP; сами адреса не публикуются. Для последующих нативных запусков использовалось то же окружение без изменения настроек сети, но причинность одного параметра этим не доказана.

| Конфигурация | Avito | Wildberries | Что проверялось |
| --- | --- | --- | --- |
| Headed Chrome/Patchright через `launchPersistentContext` | 439 | 498 | Одна начальная загрузка |
| Официальный Docker/Fortress 153.0.8010.36 | 403, признаки отказа/проверки | 498 | Одна начальная загрузка |
| Нативный Chrome с минимальными аргументами и ненулевым портом; позднее подключение Patchright | 200 | 200 | Главная страница и её публичный текст |
| Новый нативный запуск через полный модуль Alive, с текущим механизмом подписания | 200, `ready`, текст доступен | 200, `ready`, текст доступен | Главная страница, затем действие `read`; помощь не потребовалась |

Это небольшие функциональные проверки, а не статистическое измерение вероятности доступа. Они не подтверждают поиск/фильтрацию, вход, покупки, обход действующего бана, работу на будущем сервере или неизменность результата в будущем. Разные первые профили и время испытаний также ограничивают сравнение.

Обычный ранний эксперимент с `--remote-debugging-port=0` не показал готовых страниц. В документации Chrome/MDN этот параметр указан среди условий включения `navigator.webdriver`. В последующем минимальном запуске использован ненулевой порт; измерены `webdriver:false`, обычный `Chrome/155` и успешные ответы. Это не доказывает, что порт был единственной причиной различия: также отличаются остальные аргументы запуска и момент подключения драйвера. ### Что реализовано

- Нативный запуск с минимальными параметрами, выделенным постоянным профилем, ненулевым loopback-портом и проверкой PID/идентичности CDP-сервера. Сохраняются существующие профили пользователей; личный стандартный профиль Chrome не читается и не копируется.
- Первая неподписываемая целевая страница загружается до подключения драйвера. Для разрешённого подписания используется обычная навигация после подключения транспорта. Повторная загрузка уже открытой первой страницы не выполняется.
- Ограниченное пассивное ожидание автоматической проверки; ручные виджеты и приватный ввод остаются за человеком. Поддержано распознавание SmartCaptcha по документированным контейнерам и полю ответа; токены не экспортируются.
- Раздельные состояния доступа и обработка нестандартных HTTP-ошибок без объявления успеха. Ошибка отдельного Node API-клиента не вызывает пульт для посторонней страницы.
- Общий бюджет переходов по origin для приватных разговоров, `Retry-After` и резервный `X-Ratelimit-Retry`.
- Информация о фактической версии/режиме и диагностика. Выбор доверенного нативного Chromium/Fortress-бинарника остаётся настройкой оператора, с отдельным профилем каждого разговора и без тихой подмены движка при ошибке.
- Проверка геометрии стрима: обрезанный нативный кадр не выдаётся за полную страницу. Масштабированный кадр сохраняет правильные координаты; несовместимая поверхность использует ограниченный поток снимков CSS-размера вне очереди ввода.

Настройки и команды: [BROWSER.md](BROWSER.md#browser-compatibility-and-access). Проверки включают настоящий нативный Chrome, владение процессами/восстановление/очистку, два изолированных пользовательских пульта, закрытие и повторное открытие, приватный ввод, отзыв и возврат управления, а также клики у нижнего края изображения. Реальный Telegram WebView телефона и полноценные пользовательские сценарии маркетплейсов остаются отдельной приёмкой.
