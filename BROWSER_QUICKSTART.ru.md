# Подключение телефона к браузеру Alive

Для первой проверки можно запускать браузер на своём Mac. Сервер и собственный домен для этого не нужны. По умолчанию используется Patchright с постоянным профилем Chrome и плавными действиями мыши/клавиатуры. Chrome должен быть установлен; зависимости проекта устанавливаются через `npm ci` или `pnpm install --frozen-lockfile`.

## 1. Включить браузер

В каталоге проекта:

```sh
npm run browser -- setup
npm run browser -- doctor
```

`setup` сохраняет настройки в `alive.config.local.json`, добавляет `browser` к существующим разрешённым инструментам и сохраняет другие настройки. `doctor` показывает, где запускается Alive, найден ли Chrome, настроен ли Telegram и привязан ли телефон. Неполная настройка возвращает код завершения 1.

На Linux ARM64 выбирается Chromium; установите его через `npx patchright install --with-deps chromium`. Для окна браузера нужен графический сеанс, либо задайте `--headless`. Телефон с Debian можно проверить после выбора и установки системы; ждать его покупки для разработки браузера не требуется. Новый движок не снимает уже существующий бан Avito.

## 2. Получить токен бота

Если у проекта уже есть Telegram-бот, попросите владельца предоставить его токен через принятый в проекте способ передачи секретов. Если нужен отдельный бот, откройте в Telegram официального [@BotFather](https://t.me/BotFather), отправьте `/newbot` и выполните его инструкции.

Сохраните токен локально в исключённый из Git файл `.env`:

```dotenv
ALIVE_TELEGRAM_TOKEN=YOUR_BOT_TOKEN
```

Не отправляйте токен в переписку и не добавляйте его в коммит. Telegram-модуль должен быть включён. Если в конфигурации есть `allowedChatIds`, ваш личный чат должен быть разрешён этим списком.

## 3. Привязать личный чат

```sh
npm run browser -- pair
```

Команда выведет имя бота и одноразовую команду `/browser_pair ...`. Скопируйте её в **личный чат** с этим ботом в течение 10 минут. Telegram ID определится автоматически. Команда привязки не попадёт в историю агента; повторно использовать её нельзя. Привязанный пользователь также добавляется в динамический список разрешённых пользователей Telegram.

Если Alive уже работает с новой версией кода, привязку обработает его Telegram-модуль. Иначе CLI временно запускает только Telegram, без модели. Не запускайте второй процесс для того же бота из другого каталога или на другом сервере.

## 4. Проверить управление с телефона

Установите официальный [cloudflared](https://developers.cloudflare.com/tunnel/downloads/). На Mac с Homebrew:

```sh
brew install cloudflared
npm run browser -- serve --tunnel
```

CLI сам получит временный HTTPS-адрес и отправит в привязанный Telegram-чат одноразовую ссылку. Откройте её на телефоне, введите текст в демонстрационную страницу, нажмите её кнопку и затем **Готово — вернуть агенту**. Изображение, касания, перетаскивания, прокрутка и ввод передаются в ту же сессию Chrome. Остановить демонстрацию можно через Ctrl+C; временный адрес после этого перестанет работать.

Если `cloudflared` установлен не в PATH, добавьте `--cloudflared /absolute/path/to/cloudflared`. Для проверки без Telegram используйте `serve --local --tunnel`; ссылка будет показана в терминале. Для проверки на том же компьютере достаточно `serve --local`.

Quick Tunnel предназначен для разработки и тестов, не гарантирует доступность и меняет адрес при каждом запуске. Это HTTPS-доступ к панели, а не регистрация агента в Cloudflare. Для постоянной работы настройте стабильный HTTPS-адрес через именованный туннель или обратный прокси; примеры лежат в `deploy/browser/`.

CLI ждёт сообщения о зарегистрированном соединении, прежде чем выдавать ссылку. Если сеть блокирует исходящий TCP 7844, туннель не запустится: проверьте сеть/VPN или используйте сервер с доступом к Cloudflare. Созданное имя `trycloudflare.com` само по себе не означает работающее соединение.

## 5. Включить браузер в обычном Alive

После настройки постоянного адреса:

```sh
npm run browser -- setup --public-url https://YOUR_BROWSER_DOMAIN
npm run browser -- doctor --online
npm run run
```

Перед запуском обычного Alive остановите демонстрацию. Для режима без графического интерфейса добавьте к `setup` флаг `--headless`. Модель и остальные интеграции Alive настраиваются отдельно от браузера.

## Web Bot Auth

Для подписи запросов нужен постоянный HTTPS-адрес и список точных HTTPS origins, на которых оператор разрешает подписанное обращение:

```sh
npm run browser -- setup --public-url https://YOUR_BROWSER_DOMAIN --sign-origins https://AUTHORIZED_SITE
```

CLI создаёт Ed25519-ключ с правами 0600, сохраняет путь к нему в `.env` и публикует подписанный каталог открытого ключа. Существующий ключ не заменяется. Затем владелец регистрирует каталог через Bot Submission Form в своём аккаунте Cloudflare: **Verification Method → Request Signature**, URL каталога — `https://YOUR_BROWSER_DOMAIN/.well-known/http-message-signatures-directory`.

Подпись подтверждает личность агента. Решение о разрешении доступа остаётся за сайтом. Обход блокировок и скрытие автоматизации не входят в эту интеграцию. Подробности, ограничения и проверки описаны в [BROWSER.md](BROWSER.md).

Для отдельного постоянного каталога ключа без покупки домена есть [Worker на workers.dev](deploy/browser/identity-worker/README.md). Его адрес задаётся через `--identity-url` и не меняется вместе со ссылкой на телефон. В текущей панели Cloudflare форма находится в **Application security → BotBase → Submission form**; [официальная ссылка](https://dash.cloudflare.com/?to=/:account/configurations/verified-bots) ведёт туда автоматически.
